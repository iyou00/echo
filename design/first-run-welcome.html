设 计 决 策

①   为 什 么 累 加 显 示 不 是 切 换

  • 用户可能装完软件去倒水 / 接电话,5 秒内不在屏幕前
  • 累加显示意味着 — 晚回来 30 秒,第一行还在那等你
  • 切换显示则前两帧错过就错过了,失去仪式

②   为 什 么 不 自 动 进 入 onboarding

  • 这是 Echo 对用户说的第一个词 · 仪式必须由用户主动结束
  • "没问题"这个动作让用户第一次回应 Echo — 这是关系的开始
  • 自动跳转 = 把用户当成被流程拖着走的人,违反 Echo 的"朋友感"

③   为 什 么 没 有 "跳 过" 按 钮

  • 这一段 6 秒一辈子只看一次,不需要跳过
  • 有跳过按钮 = 暗示这是流程,削弱仪式感
  • 用户真不想看,会直接关掉 app(下次再开依然看到这一段)

④   为 什 么 第 3 行 字 号 比 前 两 行 小

  • 第 1、2 行是陈述句 / 自我介绍,字号 22px 主标
  • 第 3 行是问句 / 邀请,字号 19px,权重次一档
  • 视觉重心仍在前两行的"你好 / 我是 Echo",问句作为引出按钮的桥梁

⑤   为 什 么 按 钮 不 用 主 色 实 心

  • 主程序里所有"主操作"按钮都是主色实心(发送 / 播放)
  • 启动画面的按钮是邀请,不是命令 · 描边比实心更克制
  • hover 时变实心 — 用户主动伸手时,按钮才"亮起"

⑥   触 发 条 件

  • 检查 localStorage.firstRunCompleted · 不存在 → 显示启动画面
  • 用户点"没问题" → 写入 firstRunCompleted = true + 时间戳
  • 之后所有启动 → 走 echo 字母闪屏 → 进 app 主页
  • 用户重置数据 / 重装,标记会清空,启动画面会再次出现

⑦   与 现 有 echo 字 母 闪 屏 的 关 系

  • 每次启动:echo 字母闪屏(0.8s 自动消失) → 主程序
  • 第一次启动:echo 字母闪屏(0.8s 自动消失) → 这个仪式画面 → 用户点击 → onboarding
  • 两个东西互不冲突,前者是 splash,后者是 welcome
