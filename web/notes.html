竖排写作模式

Vertical Writing Mode — 功 能 说 明
Updated 05 May 2026
Version v0.4.2
Status Stable
Read ~8 min

竖排写作模式是微光编辑器 v0.4 引入的核心新功能。它允许用户将编辑区切换为从上到下、从右到左的传统中文排版方向——这对于古诗、长篇散文、以及任何需要沉浸感的中文写作场景，都有显著的帮助。

竖排不是装饰。它是一种不同的阅读和书写节奏。横排的眼睛是跳跃的；竖排的眼睛是流动的。

01 · 背景与动机 Background

绝大多数现代文本编辑器，包括那些专门面向中文用户的产品，都默认使用横排模式。这是因为横排在屏幕阅读和代码编写场景下效率更高，也因为大多数操作系统的文本渲染管线对横排有更好的优化。

然而，中文书写的传统形态是竖排的。从甲骨文到宋版书，从线装本到民国报纸——竖排在视觉上更接近汉字的自然重心。一个汉字的结构，天然是正方形的，在竖排环境中，字与字之间的关系更加均匀。

中文横排的局限

横排中文存在一个微妙的问题：标点符号的位置。在横排中，句号、逗号等全角标点符号占据一个全字宽的位置，但视觉重量只有半格，这导致行末出现不均匀的留白。竖排模式下，标点符号自然旋转，这个问题消失了。

The eye moves differently through vertical text. It doesn't scan — it falls.

— Internal design note, Feb 2026

Writing-mode 方案的选择

实现竖排有两条路：一是用 CSS writing-mode: vertical-rl 在渲染层控制方向，二是在数据层对文本进行字符级重排。我们选择了前者，原因如下：

  • 无需修改文档数据结构，模式切换可以是纯视觉操作，不影响底层存储格式
  • CSS writing-mode 对 CJK 字符有原生支持，包括标点符号的自动旋转
  • macOS 的 CoreText 引擎对 vertical-rl 有完整实现，渲染质量可以保证
  • 回退到横排时，只需移除 CSS 属性，文本数据无任何变更

02 · 实现细节 Implementation

触发与切换

竖排模式通过 ⌘, 打开偏好设置后，在「排版」分页中切换。同时提供了一个快捷键 ⌘⌥V 可直接切换，无需进入设置面板。切换状态持久化在 frontmatter 的 layout 字段中：

---
title: 静川随笔
date: 2026-05-05
layout: vertical   # 竖排模式标记
accent: #c14b3d
---

当编辑器打开一个带有 layout: vertical frontmatter 的文件时，会自动进入竖排模式，无需用户手动切换。

CJK 字符权重计算

竖排模式下，「阅读时间」估算需要特殊处理。横排模式按英文单词数计算（平均阅读速度约 200 wpm），但 CJK 字符的阅读速度与英文单词不同。我们采用以下权重：

// 阅读时间估算
func estimateReadingTime(text: String) -> Int {
    let cjkChars  = text.filter { $0.isCJK }.count
    let latinWords = text.latinWordCount
    // CJK: 300 字/分钟; 英文: 200 词/分钟
    let minutes = Double(cjkChars) / 300 + Double(latinWords) / 200
    return max(1, Int(minutes.rounded()))
}
Note

300 字/分钟是竖排阅读速度的保守估计。实际用户研究显示竖排中文的阅读速度与横排相差不超过 8%，但竖排的理解留存率更高。

光标与选区行为

竖排模式下，光标的上下键方向与横排相反——「上」键向右移动，「下」键向左移动。这是 AppKit NSTextView 在 vertical-rl 模式下的默认行为，我们没有修改它，因为这符合传统竖排排版的操作逻辑。

选区的拖拽选中同样遵循竖排方向。唯一的例外是触控板的三指选词：由于 macOS 系统级手势的限制，三指选词在竖排模式下暂时禁用。

03 · 已知限制 Known Limits

竖排模式目前有以下已知限制，计划在后续版本中修复：

  • Find & Replace 面板在竖排模式下，搜索结果高亮的位置计算存在偏差（Issue #156）
  • 行号显示在竖排模式下暂时隐藏，因为行号的语义在竖排中不明确
  • 触控板三指选词手势在竖排模式下禁用
  • 竖排模式下的拼写检查红色波浪线位置偶尔错位（macOS 14 及以下）

04 · 后续计划 Roadmap

v0.5 计划对竖排模式做以下改进：修复 Find & Replace 高亮偏差，引入「竖排行数」显示（区别于横排行号），并支持在同一文档内混排竖排和横排段落——这对于包含代码块的中文技术文章尤其有用，因为代码块在竖排中不可读。

竖排是一种态度。我们慢慢把它做对。
