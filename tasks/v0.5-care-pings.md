> **核心理念**:
> - Echo 不弹气泡、不强行打开主程序、不发声
> - 它只是**在系统通知中心轻轻出现一下**
> - 你看到 → 点开 → 进入 Echo 主程序对应位置
> - 你没看到 → 它静静消失,不再追

## v0.5 退出标准

用户的实际体验:

1. 用一段时间(无 v0.5)→ 开启 v0.5 → 第二天感觉"咦,Echo 在合适时候来找我了"
2. 通知出现的频率"刚好" — 不烦躁,不被忽视
3. 通知文字读起来像朋友给你发的消息,不像系统提醒
4. 推歌类通知 → 点开 → 直接听到歌
5. 寒暄类通知 → 点开 → 进入 Echo 主对话
6. 邀请听音类通知 → 点开 → 进入听音页

**v0.5 不做**:
- ❌ 桌面音宠 / 视觉化形象(已决定不做)
- ❌ 通知里直接回复(用户回复 = 打开主程序)
- ❌ 复杂勿扰时段配置(只做"今天别再提醒")
- ❌ 主动语音播报(语音归听音 tab,通知是文字)

## 阶段 1 · 触发引擎(1 天)

### 1.1 时间槽位定义

```typescript
// src/main/services/care-pings/schedule.ts

interface TimeSlot {
  hour: number;       // 24 小时制
  minute: number;     // 0 / 30
  weekdayProbability: number;   // 0-1 工作日推送概率
  weekendProbability: number;    // 0-1 周末推送概率
}

export const TIME_SLOTS: TimeSlot[] = [
  // 早晨
  { hour: 9,  minute: 0,  weekdayProbability: 0.5, weekendProbability: 0.3 },
  // 上午
  { hour: 11, minute: 0,  weekdayProbability: 0.4, weekendProbability: 0.2 },
  // 下午犯困点
  { hour: 14, minute: 30, weekdayProbability: 0.6, weekendProbability: 0.4 },
  // 下午
  { hour: 16, minute: 30, weekdayProbability: 0.5, weekendProbability: 0.3 },
  // 晚饭
  { hour: 19, minute: 0,  weekdayProbability: 0.5, weekendProbability: 0.6 },
  // 晚上
  { hour: 21, minute: 30, weekdayProbability: 0.6, weekendProbability: 0.7 },
];
```

- [x] 已实现时间槽位 — `src/main/services/carePings.ts`

**说明**:
- 每天 6 个时间槽位
- 工作日下午 14:30 概率最高(60%) — 这是公认的犯困时段
- 周末晚上概率高 — 用户更可能在听音乐
- **平均每天实际推送数量** ≈ 槽位 × 平均概率 ≈ 6 × 0.5 = **3 条**

### 1.2 频率档位(用户可调)

```typescript
type CareFrequency = 'gentle' | 'normal' | 'frequent';

const FREQUENCY_MULTIPLIER = {
  gentle:   0.5,    // 平均每天 1.5 条
  normal:   1.0,    // 平均每天 3 条 (默认)
  frequent: 1.5,    // 平均每天 4.5 条
};
```

- [x] 已实现频率档位 — gentle / normal / frequent

### 1.3 调度器

```typescript
// 启动时注册定时任务,每个时间槽位到点检查
import cron from 'node-cron';

export function setupCarePings() {
  for (const slot of TIME_SLOTS) {
    cron.schedule(`${slot.minute} ${slot.hour} * * *`, async () => {
      await maybeTriggerCarePing(slot);
    });
  }
}

async function maybeTriggerCarePing(slot: TimeSlot) {
  // 1. 检查用户开关
  const settings = await db.settings.get();
  if (!settings.carePings.enabled) return;
  
  // 2. 检查"今天别再提醒"
  if (await isMutedToday()) return;
  
  // 3. 检查最小间隔(90 分钟)
  const lastPingAt = await db.carePings.getLastSentAt();
  if (lastPingAt && minutesSince(lastPingAt) < 90) return;
  
  // 4. 全屏检测(如果实现了)
  if (await isUserInFullscreen()) return;
  
  // 5. 概率判断
  const isWeekend = [0, 6].includes(new Date().getDay());
  const baseProb = isWeekend ? slot.weekendProbability : slot.weekdayProbability;
  const finalProb = baseProb * FREQUENCY_MULTIPLIER[settings.carePings.frequency];
  if (Math.random() > finalProb) return;
  
  // 6. 选类型(40% 推歌 / 30% 寒暄 / 30% 邀请听音)
  const type = pickPingType();
  
  // 7. 生成 + 推送
  await generateAndSend(type);
}
```

- [x] 已接入调度器 — 启动注册,设置变更后重排

```typescript
function pickPingType(): PingType {
  const r = Math.random();
  if (r < 0.4) return 'recommend_track';     // 40% 推歌
  if (r < 0.7) return 'casual_check';        // 30% 寒暄
  return 'voice_invite';                      // 30% 邀请听音
}
```

## 阶段 2 · 类型 1 · 推歌通知(1 天)

### 2.1 完整链路

```
[时间槽位触发]
    ↓
[确定类型 = recommend_track]
    ↓
[第一步:find_tracks() 拿候选]
    │ - vibe 描述基于此刻情境(时间、天气、用户最近行为)
    │ - 例 vibe: "下午三点 · 犯困 · 慢节奏 · 治愈"
    │ - 返回 3-5 首候选
    ↓
[第二步:从候选选一首(简单规则,不调 LLM)]
    │ - 优先选用户 affinity > 0.7 的
    │ - 优先选最近 3 天没推过的
    │ - 取 score 最高的
    ↓
[第三步:调 LLM 生成文案]
    │ - 输入:类型 / 时间 / 天气 / 选定的歌名 / 最近对话 / day_seal
    │ - 输出:30-60 字带歌名和艺人的通知文案
    ↓
[第四步:发送系统通知]
    │ - title: "Echo"
    │ - body: LLM 生成的文案
    │ - payload: { trackId, type: 'recommend_track' }
    ↓
[用户点击]
    ↓
[显示主窗口 → 切到对话 tab → 自动播放这首歌 + Echo 在对话里说一句"来了"]
```

## 给开发 AI 的工作准则

1. **通知文案永远走 LLM,不走模板** — 即使为了省 token 也不要做模板池
2. **通知必须可静音 + 可关闭** — Echo 不能成为打扰
3. **三种类型的 prompt 分开三个文件** — 不要混在一个 prompt 里
4. **数据库 `care_pings` 表用来分析效果** — 哪种类型点击率高、什么时段最有效,后期用得上
5. **Windows 不支持通知里 action 按钮**这个限制要做好降级
6. **遇到无法判断的产品决策**:写到底部 ❓ 区,不要擅自决定
