# Roadmap

## 指导原则

- **小步快跑**,每个版本可独立使用
- **先跑通人格和记忆**,再接音乐 API 和语音
- **视觉质量每版都必须达标**,不做"先丑后美"的阶段

---

## v0.1 · "能说话的Echo"(目标:2-3 周)

### 目标

Echo以基本形态"活起来":能聊天、有人格、记得你、每天写风信。但不真正播放音乐(歌曲以卡片形式展示)。

### 必须有

- [x] 产品 + 人格文档定稿
- [ ] Electron + React + TS 工程脚手架
- [ ] SQLite schema + 基础读写
- [ ] LLM 客户端(原生 fetch + OpenAI 兼容协议)接入,絮语可用
- [ ] **主界面**:聊天 + 嵌入的歌曲卡片 + 底部播放器占位(不实际播放)
- [ ] **Echo主页**(点头像打开):展示 TasteProfile
- [ ] **歌单导入**:从网易云导出的 JSON 结构化数据一键导入
- [ ] **TasteProfile 初始化**:导入后Echo主动和你对话确认它对你的理解
- [ ] **风信生成**:node-cron 每晚 22:00 自动写;可手动触发
- [ ] **风信页**:按日期翻日记

### 不做

- ❌ 实际播放音乐
- ❌ 语音输出(TTS)
- ❌ 主动推送 / 通知
- ❌ 电影
- ❌ 系统托盘

### 退出标准

用户能连续使用一周:
- 每天都能聊天
- 能打开主页看到自己的"画像"
- 每天能看到一篇风信
- 觉得"这确实像个懂我的朋友"(主观)

---

## v0.2 · "会放歌的Echo"(目标:v0.1 后 2 周)

### 目标

真正能放歌,能从推荐走到播放闭环。

### 必须有

- [ ] 直接 import `@neteasecloudmusicapienhanced/api` 到主进程(不启额外服务)
- [ ] 歌曲搜索 + 取播放链接
- [ ] HTML5 audio 实际播放
- [ ] **底部播放器**:真实波形音浪 + 上下曲 / 播放 / 暂停 / 进度条
- [ ] **拾音页**:带Echo小注的队列
- [ ] Echo推荐 → 直接点卡片播放
- [ ] 听歌记录入库 → 反馈到 TasteProfile 演化

### 不做

- ❌ 歌词
- ❌ 音质选择
- ❌ 本地文件播放

---

## v0.3 · "会说话的Echo"(目标:v0.2 后 2 周)

### 目标

语音模式上线,主动推送启用。

### 必须有

- [ ] **语音模式界面**(点麦克风按钮触发)
- [ ] 场景化 100 字文案生成(`prompts/scenario-100.md`)
- [ ] TTS 接入(候选:微软 Edge TTS / ElevenLabs)
- [ ] 文字随说话渐变展开(已说 / 正在说 / 待说 三段)
- [ ] **主动推送**:早晨问好、深夜陪聊(配置定时)
- [ ] 系统托盘图标 + 原生通知
- [ ] 关闭主窗口后主进程继续跑

### 不做

- ❌ 语音输入(用户对麦克风说话 → Echo听懂)

---

## v0.4+ · 候选特性池(优先级待定)

- 电影模块(Echo 也懂电影)
- Claude Code 自定义命令入口(从命令行唤起 Echo)
- **风信 · 打开时随机翻一页**:设置里一个开关,默认关;开启后打开风信页默认翻到一篇过去的,像翻旧日记本的惊喜
- 语音输入
- 多用户 / 多 Echo 人格切换
- 歌词 + 同步高亮
- 分享:把某个风信或某段对话导成卡片
- 导出 TasteProfile 为可视化报告
- 跨设备同步(可选,涉及云端)
