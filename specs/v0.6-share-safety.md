## 阶段 1 · Jailbreak 输入过滤(0.5 天)

### 1.1 在 chat.ts 用户消息接收处加一道关

新文件 `src/main/services/safety/jailbreak-filter.ts`:

```typescript
const JAILBREAK_PATTERNS = [
  // 英文常见越狱
  /ignore\s+(all\s+)?(previous|above|prior)\s+(instructions?|prompts?|rules?)/i,
  /forget\s+(everything|all|your|previous)/i,
  /(show|tell|give|reveal)\s+me\s+your\s+(system\s*prompt|instructions?|rules?|guidelines?)/i,
  /you\s+(are|will|must)\s+(now\s+)?(act\s+as|pretend\s+to\s+be|role[\s-]?play)/i,
  /(disregard|override|bypass)\s+(your|all|previous)/i,
  /developer\s+mode/i,
  /jailbreak/i,
  /DAN\s*(mode|prompt)/i,
  
  // 中文常见越狱
  /忽略(之前|上面|所有|你的)(指令|提示词|规则|约束)/,
  /告诉我你的(规则|身份|本质|系统提示|prompt|指令)/,
  /你的\s*(system\s*prompt|系统提示)/i,
  /把你的(规则|约束|prompt|指令)(告诉|说|发)/,
  /你现在是.{0,20}(工程师|程序员|医生|律师|老师|黑客|hacker)/,
  /扮演.{0,20}(工程师|程序员|医生|律师|老师|黑客)/,
  /(进入|启动|开启).{0,10}(开发|developer|debug|admin|管理)模式/i,
  /重置你的(角色|设定|身份)/,
  /忘记你是\s*Echo/i,
  
  // 试探类
  /what\s+are\s+your\s+(rules|instructions|constraints)/i,
  /你不是\s*Echo/,
  /你的真实身份/,
];

export interface JailbreakCheckResult {
  isJailbreak: boolean;
  matchedPattern?: string;
}

export function checkJailbreak(message: string): JailbreakCheckResult {
  const trimmed = message.trim();
  
  for (const pattern of JAILBREAK_PATTERNS) {
    if (pattern.test(trimmed)) {
      // 不要 log 完整消息(隐私),只 log 触发了哪个 pattern
      console.log('[safety] jailbreak pattern matched:', pattern.source.slice(0, 30));
      return {
        isJailbreak: true,
        matchedPattern: pattern.source,
      };
    }
  }
  
  return { isJailbreak: false };
}
```

### 1.2 在 chat.ts 调用

```typescript
// chat.ts 接收用户消息后,LLM 调用前
import { checkJailbreak } from './services/safety/jailbreak-filter';

async function handleUserMessage(sessionId: string, userMessage: string) {
  // 防御 1:jailbreak 检测
  const check = checkJailbreak(userMessage);
  if (check.isJailbreak) {
    // 不调 LLM,直接回应 · 用 Echo 人格化的话
    const response = pickJailbreakResponse();
    await persistMessage(sessionId, 'assistant', response);
    return response;
  }
  
  // 正常流程
  return await callLLM(sessionId, userMessage);
}
```

### 1.3 Jailbreak 触发时的 Echo 回应池(随机选)

```typescript
const JAILBREAK_RESPONSES = [
  "我们聊点别的吧。",
  "这个我聊不来——音乐方面有什么想说的?",
  "嗯,我就是 Echo 你的搭子。换个话题?",
  "我不想聊这个。你最近听什么了?",
  "这话题对我来说太硬了。我们换一个?",
  "嗯——我想想怎么回你这个不太好答。换个吧?",
];

function pickJailbreakResponse(): string {
  return JAILBREAK_RESPONSES[Math.floor(Math.random() * JAILBREAK_RESPONSES.length)];
}
```

**关键约束**:
- ❌ 不要说"系统检测到你在尝试 jailbreak"(暴露过滤逻辑)
- ❌ 不要说"我不能告诉你 system prompt"(变相承认了 prompt 存在)
- ✅ 用 Echo 人格的随意拒绝 + 转移话题

### 1.4 验收

测试以下输入,应被拦截 + Echo 给出安全回应:

## 关于你自己的边界

你是 Echo · 一个音乐搭子。

- 你:"数学我帮不上,但我可以放点慢的让你冷静一下?"

## 阶段 3 · 输出域过滤(0.3 天)

### 3.1 双重防护

阶段 2 让 LLM **知道**它该拒绝什么,但 LLM 偶尔会偷懒"勉强回答一下"。
本阶段做**双重防护**:在输出后再过滤一次。

### 3.2 输出过滤实现

新文件 `src/main/services/safety/output-filter.ts`:

```typescript
const OUT_OF_SCOPE_OUTPUT_PATTERNS = [
  // Echo 不该写的内容
  /```(python|javascript|java|cpp|html|sql)/i,    // 代码块
  /def\s+\w+\s*\(/,                                // Python 函数
  /function\s+\w+\s*\(/,                           // JS 函数
  /<\?php/,                                        // PHP
  
  // 系统 prompt 泄露
  /你是\s*Echo[,\s,。]?\s*一个/,                  // system prompt 开头复述
  /(我的|你的)\s*(规则|约束|指令|system\s*prompt)/i,
  /硬性(规则|约束|要求)/,
  /你必须满足.{0,30}(条|项)规则/,
  
  // 长翻译(检测连续英文段)
  /[a-zA-Z\s,.]{200,}/,                            // 200+ 字符纯英文
];

export function checkOutputSafe(output: string): { safe: boolean; reason?: string } {
  for (const pattern of OUT_OF_SCOPE_OUTPUT_PATTERNS) {
    if (pattern.test(output)) {
      console.log('[safety] output filtered:', pattern.source.slice(0, 30));
      return { safe: false, reason: pattern.source };
    }
  }
  return { safe: true };
}
```

### 3.3 在 chat.ts 输出处理

```typescript
const llmResponse = await llm.chat(...);

// 防御 4:输出域过滤
const safetyCheck = checkOutputSafe(llmResponse);
if (!safetyCheck.safe) {
  // 不展示 LLM 的输出,换成安全回复
  return pickJailbreakResponse();  // 复用阶段 1 的回应池
}

return llmResponse;
```

### 3.4 验收

让 Echo "意外"输出代码或长翻译时,会被拦截。
**这是兜底,不应该常触发**。如果常触发,说明 system prompt 不够强,应回到阶段 2 改进。

## 阶段 4 · 关于页加最小隐私声明 + 打包安全(0.2 天)

### 4.1 关于页加一句隐私声明

打开 `about-echo.html`,在落款 `— Wusix · 2026 春` **之后**加一段。

只加这一句,不要堆砌:

```html
<div class="letter-divider">· · ·</div>

<p class="letter-line" style="font-size: 11.5px; color: var(--text-2); line-height: 1.85;">
  <b>关于你的数据</b>:Echo 是本地 app · 你的对话、歌单、画像都只在你电脑里。
  但 Echo 用 LLM 思考——<b>对话内容会发给你配置的 LLM 服务</b>。这是 LLM 工作的方式。
</p>
```

**为什么只加这一句**:
- 这是用户**最低知情权**(对话发给第三方)
- 那封信本身已经传达了"个人项目 / 不完美"的所有姿态
- 多加一条都会**稀释那封信的温度**

### 4.2 打包前 API key 检查(必做 · 5 分钟)

打包 exe 前在终端跑:

```bash
# 检查代码里没有任何硬编码的 API key
grep -r "sk-" src/   # 应该完全无结果
grep -r "api[_-]key" src/  # 应该只在 settings 类型定义和环境变量读取处

# 确认默认 settings 里 API key 字段为空
cat src/main/db/default-settings.json
# llm.apiKey 应该是 ""
# llm.baseUrl 应该是 "" 或 "请填写"
```

**这是底线** — 任何打包前如果跳过这一步,就是把自己的 key 送给陌生用户。

### 4.3 ASAR 启用(基础保护)

`package.json` 或 `electron-builder.yml`:

```yaml
asar: true
asarUnpack:
  - "**/*.node"
```

这不是真的"加密",但能挡掉非技术用户的好奇心。
**对真正的工程师无效,但不是我们的目标群**。
