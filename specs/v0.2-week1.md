## v0.2 退出标准

用户的实际体验应该是这样的:

1. Echo 推荐一首歌 → **点 track card 实际响起来**
2. 底部播放条 + 实时音浪正常工作
3. 队列管理:歌完接下一首,可拖拽排序,可移除
4. 关闭主窗口后**音乐继续播**(最小化到托盘)
5. 听完 / 切歌的行为反馈到 TasteProfile,主页画像缓慢演化
6. 网易云 cookie 失效时有友好提示,不崩

**v0.2 不做**:
- ❌ 回声 / TTS / 语音模式核心功能(挪到 v0.3)
- ❌ 主动推送 / 通知
- ❌ 解灰(灰歌处理)
- ❌ 系统媒体快捷键
- ❌ 系统托盘图标(可以做最小化但不强求图标精美)

### 3.1 修改 recommender.ts

之前 v0.1 的 `play_tracks` 工具调用,只是把 ref 解析成 Track 对象推给前端。
v0.2 起,主进程拿到 Track 后**额外**调一次 `searchTrack` 拿真实 trackId 和播放链接。

- [ ] 在 `chat.ts:handlePlayTracks` 里:
  ```typescript
  for (const { ref, note } of llmInput.tracks) {
    const track = recommender.resolveRef(sessionId, ref);
    if (!track) { ... 兜底 ... }
    
    // ★ 新增:网易云搜索 + 取播放链接
    const searchResult = await netease.searchTrack(track.title, track.artist);
    if (!searchResult.ok || searchResult.data.length === 0) {
      // 卡片标"播不出来" · 不影响对话
      tracks.push({ ...track, status: 'not_playable', note });
      continue;
    }
    
    const neteaseTrack = searchResult.data[0]; // 取第一个匹配
    const urlResult = await netease.getPlayUrl(neteaseTrack.id);
    if (!urlResult.ok) {
      tracks.push({ ...track, status: 'not_playable', note });
      continue;
    }
    
    tracks.push({
      ...track,
      neteaseId: neteaseTrack.id,
      playUrl: urlResult.data.url,
      urlExpiresAt: urlResult.data.expiresAt,
      status: 'ready',
      note,
    });
  }
  ```

## 阶段 4 · 播放器实现(2.5 天)

### 4.1 主进程 vs 渲染进程的分工

**这是最容易做错的地方,看仔细:**

| 责任 | 进程 |
|---|---|
| 取 URL / 调网易云 | 主进程 |
| 实际播放(`<audio>`) | **渲染进程** |
| 频谱分析(Web Audio API) | 渲染进程 |
| 队列状态管理 | 主进程(单一来源) |
| URL 续期 | 主进程 |
| 听歌行为反馈到 DB | 主进程 |

**为什么 audio 在渲染进程**:Electron 的 audio 解码在渲染层是 Chromium 原生支持的,主进程跑不了。

### 4.2 状态管理

主进程维护 PlaybackState(单一数据源):

```typescript
// src/main/services/playback.ts
interface PlaybackState {
  current: TrackWithUrl | null;
  position: number;          // ms · 由渲染进程心跳上报
  duration: number;          // ms
  status: 'idle' | 'loading' | 'playing' | 'paused' | 'error';
  queue: TrackWithUrl[];     // 排队的歌(不含 current)
}
```

- [x] 渲染进程每 5 秒发一次心跳:`playback.heartbeat({ position, status })`
  - 完成说明:Player 每 5 秒上报播放心跳
- [x] 主进程根据心跳维护 state · 渲染进程**不**自己维护一份(避免双源)
  - 完成说明:新增 services/playback.ts 统一状态

### 4.3 IPC 接口

```typescript
// 渲染 → 主
playback.play(track: Track): Promise<void>          // 立即播这首,加到 current
playback.enqueue(track: Track): Promise<void>       // 加到队列尾
playback.next(): Promise<void>
playback.prev(): Promise<void>
playback.pause(): Promise<void>
playback.resume(): Promise<void>
playback.seek(positionMs: number): Promise<void>
playback.removeFromQueue(index: number): Promise<void>
playback.clearQueue(): Promise<void>
playback.reorderQueue(fromIndex: number, toIndex: number): Promise<void>
playback.heartbeat(state: { position: number, status: string }): Promise<void>
playback.getState(): Promise<PlaybackState>

// 主 → 渲染
'playback:state-changed' → PlaybackState  // 任何状态变化广播
'playback:url-refreshed' → { trackId, url, expiresAt }  // URL 续期
'playback:command' → { kind: 'play' | 'pause' | 'next' }  // 主进程让渲染进程做事
```
